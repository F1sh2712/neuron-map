## 本周学习内容

### 1. 什么是 PRD，为什么要写 The Bet

PRD（Product Requirements Document）不只是功能列表，核心是说清楚**为什么押注这个方向**。

本周学到了 spec-kit 的思路：PRD 里最重要的不是"做什么"，而是"**如果这个假设错了，整个产品就错了**"。我们的 Bet 是：

> 如果把教材的知识节点自动可视化成图谱，学生会在"看到图谱的瞬间"理解之前没看清楚的知识结构。

写 Bet 的好处是：它让你提前想清楚什么情况下产品会失败，而不是等到上线后才发现方向不对。

---

### 2. 如何写可被验证的验收标准（Definition of Done）

本周最大的收获之一：**验收标准不是描述"功能正常"，而是描述"什么证据证明它完成了"**。

错误写法：
```
❌ "用户可以正常登录"
❌ "体验良好"
❌ "性能提升"
```

正确写法（必须包含证据）：
```
✅ POST /api/auth/register 新邮箱 → 返回 201 + { id, email }
✅ 未登录访问 /dashboard → Network 面板可见 302 重定向
✅ 30 个节点的图谱渲染 < 2s（Chrome DevTools Performance 面板）
```

这个思路直接影响了我们设计 `/draft-issue` skill 的 R2 规则——验收标准里必须有响应码 / 数字 / 文件存在性等可观测的证据。

### 3. GitHub Issue 的正确粒度

本周把 PRD 拆成 10 个 issue，在拆的过程中理解了什么叫"可独立完成"：

- **太大：** "实现 AI 功能" → 一个人做两周还不知道做没做完
- **太小：** "给按钮加 loading 状态" → 没有独立价值，应该并入父 issue
- **合适：** "feat(ai): Claude 知识节点与关系提取" → 一个人 6 小时内可完成，有明确的输入（PDF 文本）、输出（DB 记录）和验收标准

同时学到了 label 分层体系：`type`（是什么）+ `module`（属于哪个功能）+ `scope`（改前端还是后端）+ `priority`（多紧急）四个维度，过滤 issue 时非常高效。

### 4. 力导向图（Force-Directed Graph）是什么

本周在 PRD 讨论中第一次深入了解了两种图谱布局：

**力导向：** 节点像磁铁，互相排斥、边拉近，自动找平衡位置。关联紧密的节点自然聚在一起，适合表达多对多的复杂关系网络。

**层级树状：** 从根节点往下展开，像目录，位置固定。适合有明确父子关系的内容，但无法表达跨层级的概念关联。

**决策：** NeuronMap 选力导向，因为教材里的概念不只是父子关系（比如"虚拟内存"同时关联"内存管理"和"分页机制"），树状布局无法表达这种多对多的结构。

### 5. Custom Skill 的设计思路

本周设计了第一个 Claude custom skill `/draft-issue`，学到了 prompt 工程里的几个关键模式：

- **输出格式固定化：** 不让 AI 自由发挥，强制每次输出相同结构（背景 / 用户故事 / 任务清单 / 验收标准）
- **反模式表：** 明确列出什么输入应该被拒绝，比"做什么"更重要
- **何时反问：** 信息不足时反问而不是猜，防止 AI 编造不存在的需求
- **R 规则编号：** 给每条规则编号（R1–R5），方便在测试时说"违反了 R2"而不是重复描述

## 遇到的问题

### 问题 1：Skill 工具无法调用自定义 SKILL.md

**现象：** 使用 `Skill` 工具调用 `/draft-issue` 时报错 `Unknown skill: draft-issue`。

**原因：** `Skill` 工具只能调用系统级已安装的 skill（官方插件），无法调用项目本地的 `.claude/skills/` 文件。

**理解：** SKILL.md 是给 Claude 读的**指令文件**，不是可执行插件。正确工作方式是用户输入 `/draft-issue`，Claude 读取 SKILL.md 内容并按规则执行，不需要 Skill 工具介入。

**结论：** 这是预期行为，不是 bug。skill 文件本质上是一套有结构的 system prompt，由 Claude 在对话中直接遵循。

---

### 问题 2：gh issue create 遇到特殊字符报错

**现象：** 直接把 Issue 正文作为 `--body` 参数传入时，包含 `>` 符号的内容被 shell 解析为重定向，导致命令报错。

**解决：** 改用 `--body-file` 参数，先把正文写入 `/tmp/issueN.md` 临时文件，再传文件路径。

```bash
cat > /tmp/issue2.md << 'BODY'
...issue 内容...
BODY
gh issue create --body-file /tmp/issue2.md
```
