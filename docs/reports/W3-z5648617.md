## 技术难点与解决过程

### 1. 为什么从 NextAuth 切换到 Supabase Auth

**问题：** Week 1 使用 NextAuth 做认证，但 NeuronMap 已经在使用 Supabase 做数据库和文件存储。两套系统并存带来重复配置和维护成本。

**决策：** 切换到 Supabase Auth——Supabase 本身就内置了完整的邮箱认证、OTP、密码管理和 Session 管理。不需要额外的 NextAuth 层，所有认证状态都在 Supabase 里，与数据库天然集成。

**结果：** 移除了 `next-auth` 和 `bcryptjs`；认证逻辑统一收敛到 `@supabase/ssr` 的 `createBrowserClient` 和 `createServerClient`。

---

### 2. Windows Smart App Control 阻断原生二进制文件

**现象：** 运行 `npm run build` 时报错，`@next/swc-win32-x64-msvc` 和 `@tailwindcss/oxide` 无法执行；`npx prisma db push` 报 `spawn UNKNOWN`。

**原因：** Windows Smart App Control（智能应用控制）会拦截未签名的原生 `.exe` 和 `.node` 二进制文件。Prisma 的 schema engine、Next.js 的 SWC 编译器、Tailwind 的 Oxide 引擎都是原生二进制，全部被拦截。

**解决：** 进入 Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置 → 关闭。关闭后所有工具恢复正常。

**教训：** Smart App Control 是全局系统级策略，无法为单个文件添加例外——只能彻底关闭。这是开发机器的常见配置项，生产环境不受影响。

---

### 3. Prisma schema engine 被应用程序控制策略阻断

**现象：** 即使关闭了 Smart App Control，`npx prisma db push` 仍然报"应用程序控制策略组织此文件"。

**原因：** 除 Smart App Control 外，企业级 Windows 还有 WDAC（Windows Defender Application Control）/ AppLocker 策略，更底层，不受 Smart App Control 设置影响。Prisma 的 `schema-engine-windows.exe` 触发了该策略。

**解决：** 直接在 Supabase Dashboard → SQL Editor 中手动执行 `ALTER TABLE` 语句完成数据库结构更新，绕过本地 schema engine。

### 4. Next.js 16 将 middleware.ts 重命名为 proxy.ts

**现象：** 启动 `npm run dev` 时出现警告：
```
⚠ The 'middleware' file convention is deprecated. Please use 'proxy' instead.
```

**原因：** Next.js 16 将中间件文件规范从 `middleware.ts` 更名为 `proxy.ts`，导出函数也需要从 `middleware` 改为 `proxy`。

**解决：** 将 `src/middleware.ts` 重命名为 `src/proxy.ts`，同时将导出函数名改为 `proxy`，`config` 保持不变。

### 5. Supabase 发送的是魔法链接（Magic Link）而非验证码

**现象：** 注册时调用 `signInWithOtp({ email, options: { emailRedirectTo: '...' } })`，用户收到的邮件是一个"点击链接完成验证"的邮件，而不是6位数字验证码。链接里包含 `localhost:3000`，在邮件客户端点击时无法打开（localhost 只对本地有效）。

**原因：** 当 `signInWithOtp` 传入 `emailRedirectTo` 参数时，Supabase 发送的是**魔法链接（Magic Link）**。只有不传 `emailRedirectTo` 时，Supabase 才发送**6位数字 OTP**，需要用 `verifyOtp` 在页面内验证。

**解决：**
```ts
// 错误：发送 Magic Link（链接包含 localhost，邮件客户端无法打开）
await supabase.auth.signInWithOtp({
  email,
  options: { emailRedirectTo: `${window.location.origin}/auth/callback` },
})

// 正确：发送6位OTP验证码，用户在页面输入
await supabase.auth.signInWithOtp({
  email,
  options: { shouldCreateUser: true },  // 不传 emailRedirectTo
})

// 验证
await supabase.auth.verifyOtp({ email, token: otp, type: 'email' })
```

**教训：** Magic Link 只适合生产环境（域名可以从任何设备访问）。本地开发应始终使用 OTP 验证码模式，避免 localhost 链接无效的问题。

### 6. Supabase 免费版邮件发送频率限制

**现象：** 多次测试后注册页面报错 `email rate limit exceeded`，无法发送验证码。

**原因：** Supabase 免费版内置邮件服务限制**每小时约 3–4 封**，反复测试很快触发上限。

**解决方案（两种）：**
1. **短期：** 等约 1 小时让限制重置
2. **长期（推荐）：** 在 Supabase Dashboard → Project Settings → Auth → SMTP Settings 配置自定义 SMTP 服务（推荐 [Resend](https://resend.com)，免费额度每月 3000 封），发信走自己的 SMTP，完全不受 Supabase 频率限制

---

### 7. Supabase 免费项目自动暂停

**现象：** 某次打开项目发现数据库无法连接，Supabase Dashboard 显示项目已暂停。

**原因：** Supabase 免费（Free）套餐下，项目超过 **7 天无活动**会自动暂停，不是有时间限制，而是有**活跃度限制**。

**解决：** 在 Supabase Dashboard 点击"Restore project"恢复，等待约 1–2 分钟即可。

**避免方法：** 定期访问 Dashboard 或保持开发活动；或升级到付费套餐关闭自动暂停。

## 注册流程说明

完整注册路径：

```
/register
  ↓ 输入邮箱 → signInWithOtp（无 emailRedirectTo）→ 收到6位验证码
  ↓ 输入验证码 → verifyOtp → Supabase 建立 Session
/setup（第1步）
  ↓ 输入密码（强度必须达到"中"：≥8位，含字母和数字）
  ↓ updateUser({ password }) → Supabase 设置密码
/setup（第2步）
  ↓ 输入用户名（选填）、个人简介（选填）
  ↓ POST /api/auth/profile → upsert Prisma User 记录
/dashboard
```

密码强度判定规则：
| 等级 | 条件 |
|---|---|
| 弱 | 长度 < 8，或缺少字母/数字 |
| 中 | ≥ 8 位，含字母和数字（最低门槛） |
| 强 | ≥ 12 位，含大小写字母 + 数字 + 特殊符号 |
