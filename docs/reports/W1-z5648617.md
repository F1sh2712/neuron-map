## 技术难点与解决过程

### 1. Prisma v7 必须传入 Driver Adapter

**问题：** `new PrismaClient()` 不传任何参数直接运行报错：
```
PrismaClientInitializationError: PrismaClient needs to be constructed with valid PrismaClientOptions
```

**原因：** Prisma v7 移除了传统的 Native Binary Engine，改用 WASM 查询编译器。WASM 版本无法自己读取 `DATABASE_URL` 去建立连接，必须由开发者显式传入一个 JavaScript driver adapter。

**解决方案：**
```ts
import { PrismaPg } from '@prisma/adapter-pg'

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL! })
const db = new PrismaClient({ adapter })
```

**踩坑时长：** 约 1 小时，通过阅读生成的 `src/generated/prisma/index.d.ts` 注释才发现这个要求。

---

### 2. Supabase 双 URL 配置（pgBouncer Pooler）

**问题：** Supabase 不是直接暴露 PostgreSQL，而是通过 PgBouncer 连接池转发。不同场景需要不同 URL：

| URL | 端口 | 用途 |
|---|---|---|
| `DATABASE_URL` | 6543（Transaction pooler） | Next.js 运行时查询 |
| `DIRECT_URL` | 5432（Session pooler） | `prisma db push` 和 Seed 脚本 |

**原因：** Transaction pooler 每次请求复用连接，不支持 `SET` 等 Session 级别命令，而 Prisma 的 schema push 和 seed 需要这些操作。

**解决方案：** `.env.local` 配置两个 URL，seed 脚本使用 `DIRECT_URL`，Next.js API 使用 `DATABASE_URL`。

---

### 3. Seed 脚本无法读取环境变量

**问题：** 用 `npx tsx prisma/seed.ts` 直接运行时，Prisma 提示连接失败——`DATABASE_URL` 未定义。

**原因：** Next.js 会在启动时自动加载 `.env.local`，但 `tsx` 直接运行 TypeScript 文件时没有这个机制。

**解决方案：** 在 seed.ts 第一行加入：
```ts
import 'dotenv/config'   // 手动加载 .env 文件
```

---

### 4. 为什么选 Supabase 而不是 Neon？

| 对比维度 | Supabase | Neon |
|---|---|---|
| 数据库 | PostgreSQL ✅ | PostgreSQL ✅ |
| 文件存储 | ✅ 内置 Storage（PDF 上传需要） | ❌ 无，需另配 S3 |
| 认证 | ✅ 内置 Auth | ❌ 无 |
| 免费额度 | 500MB DB + 1GB Storage | 0.5GB DB |
| 控制台 | 一站式 Dashboard | 仅数据库 |

**结论：** NeuronMap 需要 PDF 文件存储（Supabase Storage）。如果用 Neon 则需要额外配置 AWS S3 或 Cloudflare R2，增加复杂度。Supabase 把数据库 + 存储 + Auth 打包在一起，对 Week 1 阶段更合适。

## 测试方式

1. 配置 `.env.local`（参考 README）
2. 运行 seed：`npx tsx prisma/seed.ts`
3. 启动：`npm run dev`
4. 打开 `http://localhost:3000`
5. 输入账号 `admin`，密码 `admin123`，点击登录
6. 应跳转到 `/welcome` 显示"恭喜登录成功！Welcome to NeuronMap, admin"

API 直接测试：
```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"account":"admin","password":"admin123"}'
# 返回: {"success":true,"name":"admin"}
```
