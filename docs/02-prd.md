# NeuronMap — Product Requirements Document

**Version:** 1.0 · Phase 1 MVP  
**Author:** NeuronMap Team  
**Status:** ✅ Locked

---

## 1. Problem Statement

在校学生在学习教材或专业书时，能读懂每一页的文字，却**看不见知识之间的结构**。一本 300 页的操作系统教材读完，脑子里装的是碎片，而不是网络。复习时不知道从哪里入手，考试时发现"学了但没联系起来"。

> **一句话版本：** 学生在精读教材后，无法快速形成知识体系的结构性认知，导致复习效率低、知识迁移能力弱。

---

## 2. The Bet

> 如果这个假设是错的，整个产品就是错的。

**我们押注：** 如果把一本教材的知识节点和关系自动可视化成图谱，学生会在"看到图谱的瞬间"理解自己之前没看清楚的知识结构，并愿意以图谱为中心来复习和整理知识。

**反驳测试（如果以下任一成立，这个 Bet 就失败）：**
- 学生更习惯看线性笔记，不需要图谱
- AI 提取的节点质量太差，图谱看起来一团乱
- 图谱好看但学生不知道怎么用它学习

**我们认为不会，因为：** 思维导图工具（XMind、幕布）已经验证了学生对"结构化知识"的需求，NeuronMap 的差异是"自动生成"而不是手动整理。

---

## 3. Target User

**主角：小林，大二计算机系学生**

- 每学期要啃 3–5 本教材，每本 200–400 页
- 习惯 PDF 阅读，课前预习 + 考前复习两个场景都用
- 用过 XMind 手动整理知识点，但嫌麻烦，坚持不了几章
- 期望：上传一本书，5 分钟后就能"看到这本书在讲什么"

**不是我们的用户（Phase 1）：**
- 研究者整理学术论文（需要跨文档关联，v2）
- 职场人士整理会议记录（不是教材场景，v3+）

---

## 4. User Journey（核心流程）

```
① 注册 / 登录
        ↓
② 上传 PDF 教材（拖拽 or 点选，最大 20MB）
        ↓
③ 等待 AI 处理（进度条显示：文本提取 → 节点识别 → 关系构建）
        ↓
④ 查看知识图谱（交互式节点图，点击节点看详情）
        ↓
⑤ 向 AI 提问（基于图谱上下文回答，引用具体节点）
```

每一步对应原型中的一个页面，无跳跃，线性可完成。

## 5. Feature Specs

每个功能包含：描述 · Why · Done When（Definition of Done）

---

### F1 · 用户认证

**描述：** 邮箱 + 密码注册和登录，登录后进入文档列表页。

**Why：** 知识图谱是个人资产，必须与账号绑定才能做数据隔离和持久化。

**Done When：**
- [ ] 用户可用邮箱 + 密码完成注册，密码 bcrypt 加密存储
- [ ] 登录后跳转到 `/dashboard`，session 持久化
- [ ] 未登录访问 `/dashboard` 自动跳转登录页
- [ ] 登出后 session 清除

---

### F2 · PDF 上传

**描述：** 用户在上传页拖拽或点选 PDF，文件上传到 Supabase Storage，元数据存入 DB。

**Why：** 上传是整个流程的起点。Supabase Storage 处理文件存储，DB 只存 URL，避免大文件入库。

**Done When：**
- [ ] 支持拖拽 + 点选两种方式
- [ ] 上传前校验：仅 PDF 格式，≤ 20MB
- [ ] 文件上传到 Supabase `documents` bucket，URL 存入 `Document.fileUrl`
- [ ] 上传成功后自动触发 AI 处理（进入 F3）
- [ ] 上传失败给出明确错误提示

---

### F3 · AI 知识提取

**描述：** 后端读取 PDF 文本，调用 Claude API 逐段提取知识节点和关系，写入 `KnowledgeNode` 和 `KnowledgeEdge` 表。

**Why：** 这是产品核心价值的生产环节。提取质量直接决定图谱是否有用。

**设计决策：** 按页分批调用 Claude（每次 3–5 页），避免触发 Vercel 10 秒超时限制。进度写入 `Document.status` 字段供前端轮询。

**Done When：**
- [ ] PDF 文本成功提取（使用 `pdf-parse` 或类似库）
- [ ] 每个知识节点包含：名称、一句话摘要、来源页码
- [ ] 每条关系包含：起点节点、终点节点、关系类型（如"包含""依赖""对比"）、权重
- [ ] 提取完成后 `Document.status` 更新为 `COMPLETED`
- [ ] 前端可通过轮询看到进度百分比

---

### F4 · 知识图谱可视化

**描述：** 渲染 `KnowledgeNode` 和 `KnowledgeEdge` 为可交互节点图。节点大小按重要性（连接数）变化，边粗细按权重变化。

**Why：** 这是用户"打开产品的第一眼"，也是核心价值的兑现时刻。视觉上必须清晰、有层次感。

**技术选型：** 使用 `react-force-graph` 或 `D3.js`（力导向布局），在客户端渲染。

**Done When：**
- [ ] 所有节点和边正确渲染，布局自动调整无重叠
- [ ] 节点可拖拽重新布局
- [ ] 点击节点 → 右侧面板显示节点详情（名称 + 摘要 + 来源页码 + 相关节点列表）
- [ ] 图谱支持缩放和平移
- [ ] 节点数 ≤ 50 时渲染流畅（60fps）

---

### F5 · 文档管理

**描述：** 文档列表页显示所有上传文档，支持查看状态（处理中 / 已完成）和删除。

**Why：** 用户会上传多份教材，需要入口统一管理。

**Done When：**
- [ ] 列表显示：文件名、上传日期、处理状态、节点数
- [ ] 处理中的文档显示进度百分比（轮询）
- [ ] 删除文档同时删除 Supabase Storage 文件 + DB 中所有关联节点/关系

---

### F6 · AI 问答（基础版）

**描述：** 用户在图谱页底部输入问题，AI 基于当前文档的知识节点列表作为上下文回答，并在回答中引用相关节点名称。

**Why：** 图谱是"看结构"，问答是"问细节"，两者互补。用户看到节点后自然会想问"这个节点具体讲的什么"。

**范围限制（Phase 1）：** 只做单文档问答，不做跨文档。会话历史只保留当次页面访问，不持久化。

**Done When：**
- [ ] 用户输入问题后 AI 在 3 秒内开始流式输出
- [ ] 回答中明确引用节点名称（如"根据节点【虚拟内存】…"）
- [ ] 单次问答在 Vercel 10 秒限制内完成（节点列表裁剪到前 30 条）
- [ ] 空问题 / 文档未处理完成时给出提示

## 6. Constraints & Risks

| 约束 / 风险 | 具体说明 | 应对 |
|---|---|---|
| Vercel 10 秒超时 | API Route 最长执行 10 秒 | AI 提取分批调用；问答裁剪上下文 |
| Claude API 费用 | 每次提取一本 300 页教材约消耗较多 token | Phase 1 无 rate limit，靠账号隔离控制；v2 再加配额 |
| PDF 文本提取质量 | 扫描版 PDF 无法提取文本 | Phase 1 只支持可选中文字的 PDF，扫描版提示不支持 |
| 图谱节点过多 | 教材提取可能超过 100 个节点，力导向布局卡顿 | 限制单次提取最多 50 个节点；按重要性裁剪 |
| Supabase 免费额度 | 500MB 存储，2GB 带宽/月 | Phase 1 够用，提醒用户删除不用的文档 |

## 7. Open Questions

> 还没决定的问题，留给后续 sprint 讨论。

- **Q1：** ~~图谱布局是力导向（自动美观但不稳定）还是层级树状（结构清晰但僵硬）？~~ → ✅ **已决定：力导向布局**
- **Q2：** ~~节点详情页是侧边栏还是弹窗？~~ → ✅ **已决定：侧边栏**
- **Q3：** ~~AI 提取提示词是否需要针对不同学科优化？~~ → ✅ **已决定：Phase 1 使用通用 prompt，Phase 2 再分学科优化**
- **Q4：** Phase 2 是"任意文件类型"还是"多文档关联图谱"优先？
- **Q5：** 要不要做"节点笔记"功能——用户可在节点上写自己的理解？
